## 核心发现（修正既有认知）

**F1｜熄屏不冻结 timer（本方式/时长范围）**：`keyevent 26` 熄屏下（短时 64s / 长时 304s 双档实测）Chromium 仅置 `visibility=hidden`，**`setTimeout` 正常 fire（50ms 观察窗 5s 内返回）**——与 Gate-UI-4 方案 B 补验时点观察的"熄屏冻结 timer"不同（彼时场景疑为自然长时熄屏进入 Doze 深度休眠等特定条件，非电源键熄屏短/中时长的普遍行为）。该发现收窄了既有冻结结论的适用范围，**不做外推**——Doze 深度休眠场景未在本轮覆盖（未执行项披露）。

**F2｜SMB 连接经 300s 熄屏存活**：唤醒后点面包屑根段触发真实 `listDirectory` 成功（logcat 1 次）——连接会话未因熄屏中断。

**F3｜熄屏中发起连接正常完成**：熄屏态点击连接卡 → timer 未冻结 → 解密+连接链正常执行 → 30s 后探测 `connected=true`——S5-06-A 的 8s 超时防御在本熄屏方式下未触发（非必需，但保留无害）。

**F4｜S3 净效果安全**：熄屏期间断网 60s → 唤醒后**已如实失败呈现**（列表清空 + loadError Banner）——不存在旧列表冒充最新数据的路径。

## 三、缺陷与根因假设（PM 第 7 条：发现缺陷先给方案待授权）

**本轮未发现需修复的代码缺陷**。两项观察（非缺陷，登记供集成回归参考）：

1. **S3 唤醒即失败呈现的机制未明**：唤醒后列表已清空+loadError（预设"乐观保留"未发生）——疑 visibilitychange 触发自动加载失败回流。净效果安全（不冒充），机制留 S5-09 集成回归时如需再深究（不构成修复需求）。
2. **S4 终态 network_interrupted 状态条与数据已恢复并存**：重试刷新成功但连接状态条仍警示——状态保守安全（宁可提醒勿漏报），非误报；产品语义可接受。

**S4-07 冻结结论修正的影响评估**：S5-06-A 的 8s 超时与"连接幂等"在电源键熄屏方式下未触发（非必需）；保留无害且覆盖未知熄屏形态（Doze/厂商省电策略——本轮未覆盖，未执行项披露）。
