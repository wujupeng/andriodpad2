# P0-02 凭证安全闭环补充核验编码任务规划

> 本文档为 P0-02 Final Gate **第八次** PM 复审裁定 **HOLD** 的四项阻断项（SEC-01～SEC-04）的编码任务规划（第三阶段产出）。基于 `.codeartsdoer/specs/p002_cred_verify/spec.md` 需求规格（660 行，48 条 EARS 规则 + 22 异常场景）与 `docs/p0-02-r3/cred-verify-design.md` 实现方案（2026 行，五模块技术方案），将五模块技术方案分解为可执行的步骤级任务。
>
> **文档定位**：本任务规划将四项补充核验措施——私钥状态核验（模块A）、SMB 凭证范围核验（模块B）、SHA 引用影响清单（模块C）、远端验证记录（模块D）、补充证据包归档（模块E）——分解为可执行、可验收的步骤级任务清单。不涉及代码功能修改，不重做 WPS/SMB 功能测试，不修改 SmbPlugin.ts 与 M2VerificationPage.tsx，不重做五项补验。核验完成后进入 P0-02 Final Gate **第九次**复审。
>
> **设计依据**：
> - 需求规格：`.codeartsdoer/specs/p002_cred_verify/spec.md`（48 条 EARS 规则 + 22 异常场景）
> - 实现方案：`docs/p0-02-r3/cred-verify-design.md`（五模块技术方案）
> - 上一轮闭环整改报告：`docs/p0-02-r3/evidence/cred-closure-evidence.md`
>
> **执行顺序**：模块A（私钥状态核验）→ 模块B（SMB 凭证范围核验）→ 模块C（SHA 引用清单）∥ 模块D（远端验证）→ 模块E（证据包归档）
>
> **时序约束**：模块C 与模块D 可并行执行；模块D 的"历史明文不可利用"确认须在模块B 完成后；模块E 须在模块A-D 全部完成后执行。
>
> **脱敏说明**：本文档中所有命令与旧密码统一用 `***REDACTED***` 脱敏表示（实际执行时使用真实密码）。文档本身不含明文凭证，不含 SSH 私钥内容。
>
> **任务产物归档路径**：`docs/p0-02-r3/cred-verify-tasks.md`

- [ ] 执行 `ls -l ~/.ssh/pad2_cred_closure` 核验私钥文件存在性、路径与权限
