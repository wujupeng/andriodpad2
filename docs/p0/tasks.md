# PAD2 P0 完整实现阶段任务分解

> 本文档为 PAD2 P0 完整实现阶段的详细任务分解，基于 PM CONDITIONAL APPROVAL 裁定生成。P0 阶段以 M2-A WPS 技术验证门禁已通过（V1-V7 全部 PASS，2026-10-16，评审报告 `docs/m2a/gate-review.md`）为前置，将 PM 建议的 6 项首批任务（P0-01 ~ P0-06）与 M2-A 遗留风险任务（P0-07 ~ P0-09）拆解为可执行、可验收、可产出测试证据的实施任务。
>
> **PM 裁定要求**：每项任务必须明确实施步骤、验收标准（EARS 格式）、测试证据要求与失败处理定义，不得直接以功能清单替代实施任务。失败处理的核心约束为"失败时不破坏原文件"。

## 1. P0-01：SMB 文件交付与 WPS 打开

> **任务 ID**：P0-01
> **任务名称**：SMB 文件交付与 WPS 打开
> **依赖关系**：无前置依赖（M2-A 门禁已通过，技术方案已确认）
> **对应需求**：REQ-02 无感打开
> **对应设计模块**：模块 B（无感打开）B1 直接打开调度、B2 大文件流式缓存；模块 A（WPS 编辑与可靠回写）A3 WPS 文件交付
> **对应 specs/tasks.md**：第 9.3 节 WPS 文件交付、第 10.1 节直接打开调度、第 10.2 节大文件流式缓存

### 1.1 详细实施步骤

- [ ] **1.1.1 实现 SMB 文件流式缓存到本地**：从 SMB 共享读取目标文件，流式写入 `context.getExternalFilesDir(null)/smb_cache/` 目录，采用分块读写（初始值 8MB 分块），禁止一次性 `byte[]` 读取整体文件，记录缓存文件路径与源文件版本基线（SHA-256 + mtime）
  - 涉及文件：`core/edit/StreamCacheService.java`、`infrastructure/cache/FileCacheManager.java`
- [ ] **1.1.2 实现 file:// URI 构造与 Intent 启动**：构造 `file://` URI 指向缓存副本，创建 `Intent(ACTION_EDIT)`，设置 `FLAG_GRANT_READ_URI_PERMISSION | FLAG_GRANT_WRITE_URI_PERMISSION | FLAG_ACTIVITY_NEW_TASK`，启动 WPS Office
  - 涉及文件：`core/wps/WpsDeliveryHandlerImpl.java`
- [ ] **1.1.3 实现 StrictMode 配置**：禁用 VM 策略以允许 file:// URI 传递（`StrictMode.disableDeathOnFileUriExposure()`）
  - 涉及文件：`android/.../MainActivity.java`
- [ ] **1.1.4 实现 FileProvider 回退方案**：当 file:// ACTION_EDIT 启动失败时（捕获 `ActivityNotFoundException`），回退到 FileProvider + content:// URI 方式交付
  - 涉及文件：`core/wps/WpsDeliveryHandlerImpl.java`、`infrastructure/provider/SmbFileContentProvider.java`
- [ ] **1.1.5 实现文件类型→应用选择调度**：识别文件类型（.doc/.docx/.xls/.xlsx/.ppt/.pptx 等），优先选择 WPS Office，无 WPS 时回退系统选择器，无合适应用时提示用户并建议安装
  - 涉及文件：`core/wps/FileAppResolver.java`
- [ ] **1.1.6 实现打开失败如实报告**：打开失败时显示失败原因（WPS 未安装/文件损坏/权限不足），不隐藏为成功
  - 涉及文件：`orchestration/OpenOrchestrator.java`
- [ ] **1.1.7 建立编辑会话**：文件交付成功后建立编辑会话，记录会话 ID、源文件路径、缓存副本路径、版本基线、会话状态（已打开）
  - 涉及文件：`core/edit/EditSessionManagerImpl.java`、`infrastructure/db/entity/EditSessionEntity.java`

### 1.2 验收标准（EARS 格式）

1. **[用户在 SMB 共享目录中点击 .doc 文件]** → **[本组件流式缓存文件到 `getExternalFilesDir()/smb_cache/`，构造 file:// URI 启动 WPS ACTION_EDIT，WPS 成功打开文件并显示内容]**
2. **[WPS 未安装或无法处理该文件类型]** → **[本组件显示失败原因并建议安装合适应用，不伪报打开成功]**
3. **[file:// URI + ACTION_EDIT 启动抛出 ActivityNotFoundException]** → **[自动回退到 FileProvider + content:// URI 方式交付，仍无法打开时如实显示失败]**
4. **[大文件（≥100MB）打开]** → **[采用流式分块缓存，峰值内存不超过冻结上限，不将整个文件载入内存]**
5. **[缓存空间不足]** → **[提示用户空间不足，不开始下载，不覆盖已有缓存除非用户确认]**
6. **[文件交付成功]** → **[建立编辑会话，记录会话 ID、源文件路径、缓存副本路径、版本基线（SHA-256 + mtime），会话状态为"已打开"]**

### 1.3 测试证据要求

- **日志证据**：记录完整调用链日志，含 SMB 读取开始/完成时间、缓存文件路径、缓存文件 SHA-256、Intent 构造参数、WPS 启动结果（成功/失败 + 错误码）
- **截图证据**：WPS 成功打开文件界面截图（含文件名可见）
- **SHA-256 校验证据**：缓存副本 SHA-256 与远程源文件 SHA-256 比对结果（须一致）
- **回退路径证据**：file:// 启动失败时 FileProvider 回退日志（如触发）
- **会话记录证据**：编辑会话数据库记录截图或导出（会话 ID、状态、版本基线）
- **测试环境记录**：设备型号、Android 版本、WPS 版本、SMB 服务器地址、测试文件名与大小

### 1.4 失败处理

| 失败场景 | 失败处理定义 | 原文件保护 |
|---------|-------------|-----------|
| SMB 读取失败（网络不可达/认证失败） | 显示失败原因，不创建缓存副本，不启动 WPS | 远程原文件不受影响（仅读取操作） |
| 缓存空间不足 | 提示用户空间不足，不开始下载，不覆盖已有缓存除非用户确认 | 远程原文件不受影响 |
| WPS 未安装 | 提示用户安装 WPS，不创建编辑会话 | 远程原文件不受影响 |
| file:// URI 启动失败 | 自动回退 FileProvider，仍失败则如实显示失败原因 | 远程原文件不受影响，缓存副本保留供重试 |
| 缓存写入中途失败 | 删除不完整缓存副本，提示用户重试 | 远程原文件不受影响 |

## 2. P0-02：WPS 保存变更检测

> **任务 ID**：P0-02
> **任务名称**：WPS 保存变更检测
> **依赖关系**：依赖 P0-01 完成（文件已交付 WPS 打开，编辑会话已建立）
> **对应需求**：REQ-03 可靠回写（变更检测环节）
> **对应设计模块**：模块 A（WPS 编辑与可靠回写）A4 WPS 保存变更检测、A6 WPS 另存为/临时文件识别
> **对应 specs/tasks.md**：第 9.4 节 WPS 保存变更检测、第 9.6 节 WPS 另存为与临时文件识别

### 2.1 详细实施步骤

- [ ] **2.1.1 实现 FileObserver 监控缓存目录**：对 `getExternalFilesDir()/smb_cache/` 目录创建 FileObserver，监控 `MODIFY | CLOSE_WRITE | MOVED_TO | CREATE` 事件，事件触发时记录目标文件路径、事件类型、时间戳
  - 涉及文件：`core/edit/WpsSaveDetector.java`
- [ ] **2.1.2 实现 mtime 变更检测**：检测到 FileObserver 事件后，读取缓存副本 mtime，与编辑会话记录的基线 mtime 比对，mtime 变更则判定为可能保存
  - 涉及文件：`core/edit/WpsSaveDetector.java`
- [ ] **2.1.3 实现 SHA-256 内容变更检测**：mtime 变更后，流式计算缓存副本 SHA-256，与基线 SHA-256 比对，SHA-256 变更则判定为内容已变更，触发回写流程；SHA-256 未变更则判定为 mtime 误报（如 touch 操作），不触发回写
  - 涉及文件：`core/checksum/IntegrityCheckerImpl.java`、`core/edit/WpsSaveDetector.java`
- [ ] **2.1.4 实现 WPS 另存为新文件识别**：检测到 `MOVED_TO` 事件或新文件创建事件时，识别是否为 WPS 另存为操作（文件名与原文件不同），提示用户选择回写为新文件或覆盖原文件
  - 涉及文件：`core/edit/WpsSaveDetector.java`、`orchestration/EditSessionOrchestrator.java`
- [ ] **2.1.5 实现临时文件识别与过滤**：识别 WPS 生成的临时文件（`~$` 前缀、`.tmp` 后缀、`.moffice_wr_check-*` 模式），过滤临时文件，不将其误判为最终结果文件
  - 涉及文件：`core/edit/WpsSaveDetector.java`
- [ ] **2.1.6 实现暂停/恢复变更监听时机控制**：回写期间暂停 FileObserver 监听（避免回写操作触发自身变更事件），回写完成后恢复监听
  - 涉及文件：`core/edit/WpsSaveDetector.java`、`core/edit/EditSessionManagerImpl.java`
- [ ] **2.1.7 实现变更事件记录**：变更检测完成后，记录变更事件含目标 URI、变更时间、内容指纹（SHA-256）、事件类型，更新编辑会话状态为"已保存待回写"
  - 涉及文件：`core/edit/EditSessionManagerImpl.java`、`infrastructure/db/entity/EditSessionEntity.java`

### 2.2 验收标准（EARS 格式）

1. **[用户在 WPS 中编辑文件并执行保存]** → **[FileObserver 检测到 CLOSE_WRITE/MODIFY 事件，mtime 变更且 SHA-256 变更，判定为内容已变更，触发回写流程]**
2. **[文件 mtime 变更但 SHA-256 未变更（如 touch 操作）]** → **[判定为 mtime 误报，不触发回写，不显示"已保存到共享"]**
3. **[WPS 另存为新文件（文件名与原文件不同）]** → **[识别为另存为操作，提示用户选择回写为新文件或覆盖原文件，不自动假设为覆盖原文件]**
4. **[WPS 生成临时文件（~$ 前缀或 .tmp 后缀或 .moffice_wr_check-* 模式）]** → **[识别为临时文件并过滤，不将其误判为最终结果文件，不触发回写]**
5. **[回写期间 FileObserver 监听已暂停]** → **[回写操作不触发自身变更事件，回写完成后恢复监听]**
6. **[FileObserver 丢失事件（内核级限制）]** → **[应用返回前台时主动检查缓存副本 mtime 与基线 mtime，发现变更则触发 SHA-256 比对作为补充检测]**

### 2.3 测试证据要求

- **日志证据**：FileObserver 事件日志（事件类型、文件路径、时间戳）、mtime 比对结果（基线 mtime → 新 mtime）、SHA-256 比对结果（基线 SHA-256 → 新 SHA-256）
- **变更检测证据**：变更事件记录（目标 URI、变更时间、内容指纹、事件类型）
- **误报排除证据**：mtime 变更但 SHA-256 未变更场景的日志（判定为误报，不触发回写）
- **另存为识别证据**：另存为新文件场景的日志与截图（提示用户选择）
- **临时文件过滤证据**：WPS 生成临时文件的日志（识别为临时文件并过滤）
- **M2-A 对照证据**：与 M2-A V2/V3 验证结果对照（V2: mtime 变更 `1792114571920 → 1792114643000`；V3: SHA-256 变更 `8f013b03... → 8da9a6aa...`）

### 2.4 失败处理

| 失败场景 | 失败处理定义 | 原文件保护 |
|---------|-------------|-----------|
| FileObserver 事件丢失 | 应用返回前台时主动检查 mtime + SHA-256 作为补充检测 | 远程原文件不受影响（仅检测操作） |
| SHA-256 计算失败（缓存文件损坏） | 显示检测失败，提示用户重新打开文件，不触发回写 | 远程原文件不受影响 |
| 临时文件误判为结果文件 | 通过严格的文件名/路径模式匹配过滤，误判时记录日志供分析 | 远程原文件不受影响 |
| 另存为识别失败 | 默认不自动覆盖原文件，提示用户确认操作 | 远程原文件不受影响 |

## 3. P0-03：安全回写

> **任务 ID**：P0-03
> **任务名称**：安全回写
> **依赖关系**：依赖 P0-02 完成（变更检测已触发，编辑会话状态为"已保存待回写"）
> **对应需求**：REQ-03 可靠回写（项目成败点）
> **对应设计模块**：模块 A（WPS 编辑与可靠回写）A5 可靠回写引擎；模块 C（可靠传输队列）C4 完整性校验引擎
> **对应 specs/tasks.md**：第 6.3 节安全写入事务、第 9.5 节可靠回写引擎

### 3.1 详细实施步骤

- [ ] **3.1.1 实现 writeFileSafe 临时文件写入**：将本地缓存副本流式写入 SMB 共享目录的临时文件，临时文件命名规则为 `目标文件名 + ".tmp" + System.currentTimeMillis()`，存放于与目标文件相同的目录，避免多任务冲突
  - 涉及文件：`core/transfer/SafeWriteTransaction.java`、`core/edit/WriteBackEngineImpl.java`
- [ ] **3.1.2 实现临时文件 SHA-256 校验**：临时文件写入完成后，读回远程临时文件流式计算 SHA-256，与本地缓存副本 SHA-256 比对，校验通过方可执行替换
  - 涉及文件：`core/checksum/IntegrityCheckerImpl.java`
- [ ] **3.1.3 实现 SMB 原子重命名替换**：校验通过后，执行 SMB rename 操作将临时文件重命名为目标文件名（`rename(name, true)` 允许覆盖），完成原子替换
  - 涉及文件：`core/transfer/SafeWriteTransaction.java`、`infrastructure/smb/SmbJOperations.java`
- [ ] **3.1.4 实现替换前版本复核**：执行替换前再次检查目标文件版本（mtime + SHA-256），与编辑会话记录的基线比对，不一致则中止替换并提示冲突（转入 P0-04 冲突处理）
  - 涉及文件：`core/edit/ConflictDetectorImpl.java`、`core/transfer/SafeWriteTransaction.java`
- [ ] **3.1.5 实现写入失败回滚**：临时文件写入失败时，删除临时文件，原文件保持不变；校验失败时，保留临时文件供故障诊断，原文件保持不变
  - 涉及文件：`core/transfer/SafeWriteTransaction.java`
- [ ] **3.1.6 实现替换失败原文件保护**：rename 操作失败时（如 oplock/lease 文件占用、权限不足），原文件必须保持不变，临时文件保留供重试或诊断
  - 涉及文件：`core/transfer/SafeWriteTransaction.java`
- [ ] **3.1.7 实现最终校验与提交**：替换完成后，读回远程目标文件计算 SHA-256，与本地缓存副本 SHA-256 比对，校验通过方可标记回写成功，更新编辑会话状态为"回写成功"，显示"已保存到共享"
  - 涉及文件：`core/checksum/IntegrityCheckerImpl.java`、`core/edit/WriteBackEngineImpl.java`
- [ ] **3.1.8 实现残留临时文件清理**：应用启动时扫描 SMB 共享目录中超过一定时间（如 24 小时）的残留临时文件（`.tmp` 后缀），清理操作记录审计日志；未超期临时文件保留
  - 涉及文件：`core/transfer/SafeWriteTransaction.java`、`infrastructure/audit/AuditLogService.java`
- [ ] **3.1.9 实现回写审计日志**：每次回写操作（成功/失败/降级）记录审计日志，含操作时间、文件路径、版本信息（mtime + SHA-256）、结果
  - 涉及文件：`infrastructure/audit/AuditLogService.java`

### 3.2 验收标准（EARS 格式）

### 9.3 测试证据要求

- **M2-A 遗留风险关闭证据**：明确记录 V7 遗留风险已通过 P0-09 补充测试关闭（区别于 M2-A V7 仅断开 SMB 连接）
- **完整流程日志证据**：Wi-Fi 断开→保存→恢复→重连→回写→校验完整流程日志

- **重试退避证据**：Wi-Fi 断开期间重试日志（重试次数、退避时间、重试结果）
- **M2-A 对照证据**：与 M2-A V7 验证结果对照（V7: 断开 SMB 后回写，reconnectIfNeeded 自动重连成功；P0-09 扩展为 Wi-Fi 完全断开场景）

- **测试环境记录**：设备型号、Wi-Fi 配置、SMB 服务器配置

### 9.4 失败处理

| 失败场景 | 失败处理定义 | 原文件保护 |
|---------|-------------|-----------|
| Wi-Fi 完全断开 | 暂停回写任务，显示等待状态，不伪报成功 | **原文件未被破坏** |
| Wi-Fi 断开期间保存 | 回写失败，显示等待/失败状态 | **原文件未被破坏** |

| Wi-Fi 切换后会话重建失败 | 显示重建失败，提供手动重连入口 | **原文件未被破坏** |
| 长时间 Wi-Fi 断开重试耗尽 | 标记失败，保留任务供手动重试 | **原文件未被破坏** |
