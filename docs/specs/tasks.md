# 安卓平板项目2：Windows SMB 共享资源管理器 编码任务规划

> 本文档基于 `spec.md` 需求规格与 `design.md` 技术设计文档生成，将五项核心需求（REQ-01 ~ REQ-05）、WPS 保存关键技术门禁、五项关键风险缓解措施及五阶段验收门禁拆解为可执行的开发任务。任务按业务功能垂直切割，遵循依赖关系排序，覆盖从项目初始化到验收发布的完整路径。

> **PAD2-M1-G4-FAST-DECISION-01 多设备兼容策略**：PAD2 不绑定单一平板型号、Android 版本或 WPS 版本。兼容性通过三层兼容性模型（通用架构兼容 / 代表性环境验证 / 兼容性证据管理）管理。须确定最低 Android API 级别（minSdkVersion）以确保应用可安装运行，但支持多个系统版本。所有涉及设备/版本假设的任务均标注"不绑定单一设备/版本，按三层兼容性模型管理"。

> **任务门禁依赖说明（P0-2 重排）**：
> - 第 1-2 节（项目初始化 + M1 冻结）为基础前置任务，不依赖 WPS 门禁。
> - **第 3 节为 PAD2-M2 WPS 技术验证门禁，前置到所有完整实现任务之前**。WPS"打开—编辑—保存回写—冲突—断网恢复"关键路径须在代表性设备真实环境中验证通过（V1-V7）后，方可进入完整实现。
> - 第 4-10 节为完整实现任务组，**均标注"依赖：PAD2-M2 WPS 门禁通过"**。若 M2 门禁未通过，不批准进入这些任务的实现。
> - 第 11-17 节为安全、接口、UI、测试、验收与发布任务，部分依赖 M2 门禁通过（已在各节标注）。

- [ ] 将旧仓库 `wujupeng/andriodpad` 标记为只读技术资产参考，不预设代码复用
- [ ] 配置 `.gitignore`，排除 `node_modules/`、`android/app/build/`、`android/.gradle/`、本地凭据文件等

### 1.2 搭建项目脚手架（Capacitor 8 + React + TypeScript + Android Java）
- [ ] 初始化 Capacitor 8 项目骨架，包含 `package.json`、`capacitor.config.ts`、`tsconfig.json`
- [ ] 初始化 React + TypeScript 前端工程，配置 Vite 或 Webpack 构建链
- [ ] 初始化 Android 原生工程 `android/`，配置 `build.gradle`、`app/build.gradle`，最低支持 Android API 26+（minSdkVersion = API 26 已冻结，PM 批准），目标版本 targetSdkVersion 候选值 API 36（待兼容性评估后冻结），支持多版本，不绑定单一版本，按三层兼容性模型管理
- [ ] 配置 AndroidManifest.xml 最小权限集（按 Android API 级别收敛，见下方权限收敛策略）

> **Android 最小权限集收敛策略（P1-3、P1-7）**：
> - **targetSdkVersion < 29（Android 7.x-8.x，传统存储）**：`INTERNET`、`ACCESS_NETWORK_STATE`、`ACCESS_WIFI_STATE`、`READ_EXTERNAL_STORAGE`、`WRITE_EXTERNAL_STORAGE`、`FOREGROUND_SERVICE`
> - **targetSdkVersion >= 29（Android 9+，SAF/分区存储）**：`INTERNET`、`ACCESS_NETWORK_STATE`、`ACCESS_WIFI_STATE`、`FOREGROUND_SERVICE`；本地缓存读写通过应用私有目录（`getExternalFilesDir()`）或 SAF，**不申请** `READ/WRITE_EXTERNAL_STORAGE`
> - **targetSdkVersion >= 30（Android 11+）**：同上，`MANAGE_EXTERNAL_STORAGE` 为**最后手段**，须证明无替代方案后才考虑申请并须 Google Play 审查
> - 所有版本均须：`FOREGROUND_SERVICE`（传输队列后台服务）、网络权限（SMB 通信）
> - 须根据 M1 冻结的 `minSdkVersion` 与 `targetSdkVersion` 最终确定权限清单，避免不必要或已不适用的权限

> **P1-7 三个 Android 版本概念区分（须明确区分，不能互相代替）**：
> - `minSdkVersion`：应用最低支持的 Android 版本（须确定，支持多版本），决定可使用的 API 下限。
> - `targetSdkVersion`：应用声明面向的目标 API 级别，决定系统对应用应用的兼容行为限制。
> - 实际设备系统版本：决定设备上实际的权限授予行为与文件访问行为，须在实际设备版本上验证，按三层兼容性模型管理。
> - `<29`、`>=29`、`>=30` 的 targetSdkVersion 划分**不能直接代替 Android 版本兼容性测试**，须在最低支持版本以上按三层兼容性模型逐版本验证，不绑定单一版本。

> **P1-7 须在实际设备上验证的 API 行为**：
> - 前台服务类型（foreground service type）：传输队列后台服务的前台服务类型声明与行为（Android 14+ 须声明 `foregroundServiceType`）
> - 后台传输限制：后台传输任务在不同 Android 版本下的限制（如 Android 12+ 后台传输限制）
> - SAF 持久化授权（persistable URI permission）：`takePersistableUriPermission` 在不同版本下的有效性
> - 缓存目录行为：`getExternalFilesDir()`、`getCacheDir()` 等缓存目录在不同版本下的行为与清理策略

> **P1-7 MANAGE_EXTERNAL_STORAGE 策略（最后手段）**：
> - 不应作为默认方案。`MANAGE_EXTERNAL_STORAGE` 为最后手段，须先证明无替代方案后才考虑申请。
> - 如果产品设计只需要应用私有缓存与用户主动授权的 SAF 目录，应优先验证能否不申请该权限。
> - 申请前须证明应用私有缓存（`getExternalFilesDir()`）与 SAF 持久化授权无法满足需求。

## 2. PAD2-M1 需求与架构冻结

### 2.1 冻结兼容性与协议要求（PAD2-M1-G4-FAST-DECISION-01 多设备兼容策略，PM Gate Review 最终裁定）
- [x] 确定最低 Android API 级别（minSdkVersion）：API 26 / Android 8.0（附技术依据：Capacitor 8 要求 API 22+；SAF 持久化授权 API 26+ 行为更稳定；Keystore API 23+ 支持完善；企业平板 2018 年后大多 Android 8.0+），写入 spec.md 与 design.md，支持多版本，不绑定单一版本 — **已冻结（PM 批准）**
- [x] 确定 targetSdkVersion 候选值：API 36（Android 16），从 API 33-34 修订为 API 36（2026 年 8 月 31 日起 Google Play 要求 API 36+），PAD2 通过企业内部 APK 分发，待兼容性评估后冻结 — **候选值待兼容性评估（退回修订）**
- [x] 建立代表性设备清单首批组合：荣耀 9X（已知现有设备，作为第一条基线）+ Android 版本（荣耀 9X 实际系统版本）+ WPS 版本（当前安装版本 + 最新稳定版），不限定平板品牌，以实测证据管理 — **有条件批准（具体版本号 M2 实测记录）**
- [x] 确定 WPS 测试目标：首批代表性测试组合（荣耀 9X + 当前 WPS 版本 + 最新稳定版），明确标注为"测试目标"不是"测试结论"，后续通过三层兼容性模型扩展 — **有条件批准**
- [ ] 冻结支持 SMB 协议版本（建议 SMB2/3，不支持 SMB1），评估 SMB3 端到端加密支持
- [ ] 冻结认证策略（NTLMv2 或 Kerberos，禁用 NTLMv1）
- [ ] 将三层兼容性模型写入 spec.md 与 design.md，确认参数状态分类清晰
- [ ] 执行 targetSdkVersion = API 36 兼容性评估（验证 Capacitor 8、插件、文件访问、前台任务和 SMB 实现在 API 36 下的兼容性），评估通过后将状态更新为"已冻结" — **待兼容性评估**

> **PM Gate Review 最终裁定（PAD2-M1-G4-FINAL-CLOSURE-01 修订）**：
> - **已冻结（PM 批准）**：minSdkVersion = API 26（Android 8.0，附技术依据）
> - **候选值待兼容性评估（退回修订）**：targetSdkVersion = API 36（Android 16），须完成 Capacitor、插件、文件访问、前台任务和 SMB 实现兼容性评估后冻结
> - **待业务确认（M2/M4 决策依赖）**：目标并发用户数（须明确预计同时使用人数、服务端容量及压力测试验收范围；不可将客户端会话数 5 或任务数 3 等同于系统目标并发用户数）
> - **有条件批准（具体版本号 M2 实测记录）**：WPS 首批测试目标（荣耀 9X + 设备实际 Android 版本 + 当前安装 WPS 版本 + 最新稳定版）
> - **初始值待 M2 验证（须明确验收口径后冻结）**：核心操作成功率目标（初始值 ≥99.5%）、恢复时间目标（初始值 ≤30s）、传输超时阈值（初始值 300s）、并发会话上限（初始值 5）、并发任务上限（初始值 3）、分块大小（初始值 8MB）、重试上限（初始值 5 次）
> - **M1 冻结为策略规则（已定）**：平板品牌不限定、Android 版本范围（多版本兼容）、WPS 版本范围（已验证版本清单管理）、三层兼容性模型
> - **留待后续实测确定（M2/M4 产物）**：目录枚举响应上限（建议首屏 2s）、大文件基线（建议 1 GiB）、批量文件基线（建议 10,000 个）、WPS 已验证版本清单、已验证环境清单
> - **参数状态严格区分**："初始参数待验证"（M2 待验证初始基线参数标注为"初始值待 M2 验证"）与"已验证兼容"（只有经过 M2 实测验证的参数才能标注为"已验证"）
> - **M1 门禁最终状态：CONDITIONAL PASS** — 批准进入 M2，保留 M1 CLOSED 状态待 targetSdkVersion 兼容性评估、并发用户数业务确认和各项参数验收口径正式写入并核验。

> **P1-4 WPS 兼容范围门禁循环修订说明（PAD2-M1-G4-FAST-DECISION-01 调整）**：
> - M1 阶段仅冻结"测试目标"（代表性设备清单 + 计划测试 WPS 版本清单），不提前认定 WPS 兼容性已验证。
> - M2 阶段（第 3 节）逐设备/逐版本验证实际兼容性，记录打开/编辑/保存/回写/冲突/断网恢复结果。
> - M2 门禁通过后，将实际通过验证的组合写入已验证版本清单，未测试组合标记为"未验证"，已验证环境清单持续更新。
> - 核心原则：M1 可以冻结"测试目标"，不能提前冻结"测试结论"。不绑定单一设备/WPS 版本，按三层兼容性模型管理。

## A.4 两个关键修改点

### A.4.1 targetSdkVersion 从 API 33-34 改为 API 36

- 2026 年 8 月 31 日起 Google Play 要求 API 36+
- PAD2 通过企业内部 APK 分发，将 API 36 作为技术评估目标，确认兼容后再冻结
- minSdkVersion = 26 与 targetSdkVersion = 36 不矛盾
- 状态标注为"候选值 API 36（待兼容性评估后冻结）"

### A.4.2 并发用户数与客户端并发限制分开

- **客户端并发会话上限（5）**：单个平板同时连接的 SMB 共享数
- **客户端并发任务上限（3）**：单个平板同时执行的传输任务数
- **系统目标并发用户数**：同时使用 PAD2 的用户总数，影响服务端容量规划
- 状态改为"待业务确认（M2/M4 决策依赖）"
